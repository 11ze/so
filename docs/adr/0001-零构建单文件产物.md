# ADR-0001：零构建、单文件产物、源码多文件

- 状态：已接受
- 日期：2026-08-19

## 背景

so 是部署在 Cloudflare Workers 上的搜索聚合站。曾有架构审查建议：把客户端脚本做成真实 ES 模块、经构建期打包以实现前后端校验逻辑同源。这要求引入构建步骤（esbuild 预打包 + wrangler custom build）。

另一条既有约束：部署产物必须是一份单文件自包含 HTML（CSS/JS 全内联、零外部请求），这是 Worker 单价部署、免静态托管的基础。

## 决策

1. **零构建**：不引入任何打包/预编译步骤。多文件源码靠 wrangler 原生打包（esbuild）+ `rules` 文本导入（`template.html` / `styles.css` / `client.js` 以 Text 模块导入，运行时组装成单文件 HTML）。
2. **产物单文件**：响应始终是一份自包含 HTML，不加载外部 JS/CSS 资源。
3. **源码多文件**：复制/部署单位是「clone 项目 + `wrangler deploy`」；若需分享部署，用 git 仓库 + Workers Builds 连接，而非单文件粘贴。
4. **不追求前后端逻辑同源**：不以「同源」为由引入构建。安全策略是出口安全（`textContent` 渲染、`encodeURIComponent` 跳转、服务端渲染前二次校验），而非客户端输入校验。

## 后果

- 客户端脚本 `client.js` 以文本形式导入，**不能 import 服务端模块**——任何需要前后端共享的逻辑，要么接受两份实现，要么像删除客户端校验那样从出口上消除需求。
- 修改 `client.js` 后需重新部署才能生效（无热构建）。
- 未来的架构审查不应再建议：加构建步骤、拆微前端、把客户端脚本模块化打包。
- wrangler.toml 的 `rules` 是唯一允许的「类构建」配置点。
